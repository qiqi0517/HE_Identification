# 下一阶段研究提案

更新：2026-09-28。GLM／DeepSeek 已完成五配置真实对照；两模型四模式完整矩阵尚未完成。现有 211 张是反复使用的开发数据。先补数据审核和稳定对照，再考虑校准、检索与专家，现阶段不同时增加多个因素。

## P1 两模型 × 四模式与复核对照

- **研究问题：** 参考图、医学知识及组合对两模型的概率预测是否有可重复贡献？
- **假设：** 参考增强可能降低概率损失，知识和组合未必有增益；复核收益依模型而异。
- **前置条件：** 完成 P2 最低审核；先排查 DeepSeek 长度截断，再冻结模型、图像、参考、提示词哈希与预算。第二模型已是 DeepSeek，无需等待 GPT 充值。
- **步骤：** 小规模检查协议；两模型各跑四模式同一队列；固定配置重复三轮；分别报告完整覆盖率和共同有效集。复核另用冻结初判比较门控，不跨 run 拼接缓存。
- **对照：** 每模型基础／参考／知识／组合；复核必须有不开复核对照。现有 211 图的一轮四模式双模型为 1688 次逻辑调用，不含重试和复核，仍只作开发实验。
- **指标：** 预先以 Brier 为主；辅以 Log loss、AUC、敏感度、特异度、覆盖率、耗时和返回 token。类别与来源分层；不要看完结果再换主指标。
- **风险：** API 内部计算与别名不同，不是严格等算力比较；同图重复不增加患者数；无效输出必须单列。
- **交付：** 八组输入快照、统一指标／差值表、重复波动、失败原因与典型错误分析。参数冻结后再对独立数据做最终评价。

## P2 数据质量与来源偏差

- **研究问题：** 模型识别的是疾病形态，还是设备、论文拼图或来源风格？Normal 标签有多强证据？
- **假设：** 按来源与标签证据分层后，总体分数会有明显变化，HE 困难子集不会随整体高分自动改善。
- **前置条件：** 原图和逐图来源可追溯；明确技术核验与需要临床人员判断的分工。
- **步骤：** 建立 219 图审核表（器官／模态／患者键／标签证据／文字标记／近重复）；先核参考与跨集合重复；扩充明确其他肝病阴性；以新版本记录修订与排除理由，不能悄悄改旧集。
- **对照：** 固定预测的全量与审核后子集敏感性分析；可靠非包虫病阴性与 Normal 来源分开；后续患者／来源隔离的新数据单独评价。
- **指标：** 标签可核验比例、患者键覆盖、冲突候选数；分来源 Brier、Log loss、覆盖率，有双类别才报告 AUC。
- **风险：** 删除难图会引入选择偏差；dHash 仅用于找候选；没有证据不能补写专项排除诊断。
- **交付：** 数据卡、审核表、版本化纳入／排除清单及新增病例需求。最低进入门槛为不存在已确认的模态错误、标签冲突和同图跨集合泄漏；未知项明示。

## P3 概率校准与可靠性

- **研究问题：** 模型自报 0.8 是否对应约 80% 的阳性比例？能否改善系统性偏高／偏低？
- **假设：** 在独立校准数据上拟合简单映射，可改善 Brier／Log loss，而排序 AUC 大体保持。
- **前置条件：** 新增独立校准集与最终测试集，两类均有可靠标签；已用于开发的 211 张不能直接当未见校准／测试。
- **步骤：** 冻结模型与模式；保存原始概率；只在校准集拟合正则化 logistic 映射（clip 后取 logit）；应用于测试预测，原始文件不覆盖；固定分箱画可靠性图。
- **对照：** 同一有效病例的原始／校准概率；各模型各模式独立拟合；样本足够再研究 isotonic，避免小样本反复选方法。
- **指标：** Brier、Log loss、可靠性曲线及每箱数量；ECE 为辅助，AUC 与覆盖率保留。
- **风险：** 患病率／来源改变会破坏映射；仅有自报概率，不能假称已对神经网络 logits 做 temperature scaling；测试集不参与拟合。
- **交付：** 独立划分、校准器版本、原始／校准概率与配对评分。无独立数据时只保留设计，不报告虚假的“校准提升”。

## P4 参考图选择策略

- **研究问题：** 相似图检索是否优于固定示例，还是加重来源偏差？
- **假设：** 控制数量和类别后，结构相似的示例可能有益；文字／设备相似则可能无效。
- **前置条件：** 多来源、两类参考池足够大且与评估集隔离。当前只有 8 图，发送全部时无检索空间；先研究从 8 中选 2 阳＋2 阴，或扩池并冻结新划分。
- **步骤：** 仅给参考池建特征索引；只用参考标签约束类别；排除已知同患者／重复组；逐图保存所选 UUID；先在开发阶段审核排名稳定性和来源集中度。
- **对照：** 固定四图、固定种子随机四图、检索四图；模型、prompt、图数和顺序规则一致。不预设 TinyUSFM 比通用编码器好。
- **指标：** 概率评分、AUC、覆盖率、检索耗时、来源多样性及重复命中比例。
- **风险：** 不用测试标签选示例、编码器或距离；相似度不是患病概率。编码器预处理只在内存派生，上传仍用原图。
- **交付：** 参考索引、逐图选择清单、三策略对照与来源审计；池太小时只报告可行性原型。

## P5 专家模型作为工具

- **研究问题：** 病灶分割或疾病分类专家能否提供有益信息，且收益超过其错误引导风险？
- **假设：** 经验证的定位／分类结果可能改善困难病例；仅有超声预训练特征并不足以成为诊断专家。
- **前置条件：** 核实权重、预处理、许可、训练来源与本任务重叠；确认输入是超声及标签含包虫病／非包虫病。分割专家需要匹配的掩膜评价，不能用分割置信度当 p_he。
- **步骤：** 先独立测专家；再设计可审计工具输出（定位或分类概率，附版本和失败状态）；冻结一个主模型后比较原图推理与加入专家结果；记录不一致病例，不静默覆盖大模型结果。
- **对照：** 原图单次、原图＋专家、成本相近的普通复核；同一病例和模型配置。编码器候选先做冻结特征＋正则化简单分类器，不把 8 张参考图当足够训练集。
- **指标：** 分类用 Brier、AUC、敏感度／特异度；分割用 Dice／IoU 并另测下游诊断增益；所有路线报告覆盖率、额外成本和失败传播。
- **风险：** TinyUSFM 无 HE 分类头；CT 模型不可直接充当超声专家；小样本、预训练重叠及错误锚定可能带来虚高分数。
- **交付：** 权重与数据核验表、专家基线及 Agent 消融表。无疾病权重时申请作者资源；无可靠标注时优先补数据，保留固定参考基线，不包装未验证工具为“专家”。

## 执行顺序与讨论问题

1. **马上：** P2 最低审核＋DeepSeek 协议稳定性检查；保留所有原始预测。
2. **短期：** P1 补齐知识／组合、重复和来源分析；已有候选在新验证集选参。
3. **数据到位后：** 独立校准数据满足才进入 P3；参考多样性足够才进入 P4；权重和任务匹配才进入 P5。

适合向导师讨论：优先“少漏判”还是整体概率质量？能否协助核验困难阴性和患者关联？先扩独立病例还是补模式消融？专家模型的阶段验收以独立预测效果还是下游增益为准？
