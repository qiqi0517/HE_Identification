# 分型专家小模型 v1：训练与评价方案

日期：2026-10-04。状态：**独立七分类专家代码已实现，真实 TinyUSFM 小规模训练检查已通过；九次正式训练与测试尚未执行**。完整命令见 [运行指南](typing-classifier-v1-runbook.md)。不改变基础 Agent、Auto Harness、原始图片或现有划分；专家训练用途映射已另存。

## 1. 推荐路线与要回答的问题

推荐先训练 **TinyUSFM 超声预训练编码器＋七分类线性头**，同时设置 ImageNet ResNet18 线性头对照，再测试 TinyUSFM 最后两层的小范围微调。先回答“小模型独立分型是否有效、成本如何”，再研究是否作为 Agent 的专家工具。

当前只有 392 张正式入选图片，适合从预训练特征开始探索。冻结特征和局部微调是两种不同的迁移学习设置，参见 [PyTorch 官方教程](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial)。模型与训练参数是本项目的预设实验选择，不是已有证据支持的最佳配置。

仓库已在 [expert_lab](../../experiments/expert_lab/README.md) 跑通 TinyUSFM 权重加载和 192 维特征提取；它目前是参考图检索工具，尚无分型能力。沿用经校验的编码器可减少实现工作。其旧文档中的二分类、旧参考池和旧测试集不适用于本方案。

本轮 [LLM 实验](../agent/typing-experiments-r1-2026-10-04.md) 的主要短板为 CE4→AE、CE1→CL；小模型应重点报告这些类别，但不能预设一定优于 LLM。当前 E1 的 70.66%、E2 的 71.86% 均为搜索集成绩，不能与小模型在同一训练集上的成绩比较。

## 2. 任务与输出

输入一张超声图片，输出七类之一，固定顺序为：

`NO_HE, CE1, CE2, CE3, CE4, CE5, AE`

标签继续使用 [分型数据 v2](../data/typing-dataset-v2.md)。AE 属于包虫病；NO_HE 表示非包虫病，不表示没有其他疾病。医院指定目录的 47 张按用户要求作为 CE2 真值纳入，原始疑似证据保留。其余 17 张分型未知的阳性图片继续排除。

模型输出 7 个 logits，`probabilities = softmax(logits)`，`predicted_type = argmax(probabilities)`，`confidence = max(probabilities)`。保留完整向量、模型版本和权重哈希。该 confidence 是未经校准的分类分数，不是患病概率，也不直接等同于实际正确率。

当前没有 CL 真值，因此不训练 CL 输出头。低 confidence 不能自动命名为 CL；未知类型的识别能力需要另有数据验证。第一版对全部可读图片给出七类预测，不设置拒答阈值；读图或推理失败记为 error，并保留在评价分母中。

小模型不生成影像解释，不伪造 `findings`。未来接入 Agent 时采用独立专家结果协议，显式标记 `confidence_kind: softmax_uncalibrated`；不能为了复用现有 LLM 解析器而填入虚构依据。

### 数据核查与来源限制

1. 合并已知同患者、同检查、同病灶及重复／近重复图片的关联。现有分组只提供已知关联隔离，医院 UUID 不能当作患者 ID；搜索侧存在一个 56 张的 Normal 保守组，图片数不等于独立患者数。
2. 训练前按统一规则检查图内诊断文字、身份信息和固定来源标记。处理规则在开发侧制定，确定性的遮挡／裁剪应用到各集合并保存派生图、掩膜和哈希；保留病灶、后方回声等判断区域，原图不覆盖。测试侧质量检查不借助预测挑图或改规则。
3. 若新患者关系跨越集合，或复核改变标签／可用图片，先生成新版清单并记录数量变化，再训练；不能为维持上表数量拆散关联组。若这些审核未完成，只能将结果标为当前内部探索划分的结果。
4. CE3 当前仅来自 Bioengineering，医院 CE2 按用户要求作为真值纳入，医院仍缺 CE3，来源与类别混杂。因此医院子集不是七类外部验证，必须报告其实际类别覆盖。
5. TinyUSFM 官方基准包含 AUL，旧调查发现其来源与本项目 Normal 来源相同。**基准收录不能证明训练泄漏，也不能证明无泄漏**；预训练、蒸馏数据重叠仍待核实。报告整体、去掉该 Normal 来源的子集、医院子集结果；后两者也不自动成为无泄漏或跨医院外部测试。依据见 [本地权重调查](../../experiments/expert_lab/research-report.md) 与 [作者仓库](https://github.com/MacDunno/TinyUSFM)。

## 4. 第一批只做三种训练配置

| 编号 | 编码器与训练范围 | 分类头 | 目的 |
| --- | --- | --- | --- |
| S1，首选起点 | TinyUSFM 全冻结 | `Linear(192, 7)`，1,351 个参数 | 检验现有超声特征能否用于分型 |
| S2，对照 | ImageNet ResNet18 全冻结 | `Linear(512, 7)`，3,591 个参数 | 检验超声预训练是否比通用视觉特征更有用 |
| S3，微调 | TinyUSFM 先训练头，再解冻最后 2 个 Transformer block 与末端 norm | 同 S1 | 检验轻微适配是否优于冻结特征 |

TinyUSFM 现有编码器约 552 万参数、192 维、12 层、12 注意力头；保持已验证的 CLS/norm 特征路径，不擅自切换随机初始化的池化层。权重文件为 `experiments/expert_lab/weights/TinyUSFM.pth`，SHA-256 为 `776a50eeff402802c8cd06e00fe9de73df4161504fa733284bc240904b48252c`。现有 `encode()` 返回 L2 归一化检索特征；本次分类使用 **L2 归一化前的原始特征**，须新增明确接口，不能混用旧检索缓存。

S2 使用 `ResNet18_Weights.IMAGENET1K_V1`，去掉原 1000 类头，保留全局平均池化特征。原模型约 1,169 万参数，替换七类头后约 1,118 万，详见 [Torchvision 模型文档](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)。编码器冻结时同时固定 BatchNorm 运行统计，验证和测试始终使用 eval 模式。

三种配置分别使用 **42、43、44 三个训练种子，共 9 次训练**。种子控制初始化、训练顺序和增强；跨设备不承诺逐位一致。另报恒预测训练多数类 NO_HE 的零训练基线。第一批不再扩展架构或大规模搜索参数。

## 5. 预处理、训练参数与停止规则

### 固定输入处理

- 输入为审核后的完整有效超声区域，RGB 三通道；灰度图复制通道。
- 第一版统一直接缩放为 `224×224`，使用 ImageNet mean/std。它延续本地 TinyUSFM 已验证处理，但存在长宽比变形和小结构丢失风险；这是项目选择，也不同于 ResNet18 官方默认中心裁剪。
- S1/S2 采用确定性输入、无随机增强，冻结编码器提取特征并缓存；缓存按图片、预处理、编码器哈希区分。仅提取 train/validation，test 特征留到最终冻结后。
- S3 训练时仅使用轻微旋转 `±5°`、平移最多 `3%`、亮度／对比度系数 `[0.9,1.1]`；验证和测试无增强。增强顺序固定为几何变换、亮度／对比度、缩放、归一化。先人工检查开发侧增强样例，不使用随机病灶裁剪、上下翻转或强弹性变形。

### 固定训练超参数

| 参数 | S1/S2 | S3 |
| --- | --- | --- |
| 损失 | 普通七类交叉熵 | 普通七类交叉熵 |
| 优化器 | AdamW | AdamW |
| 学习率 | 分类头 `1e-3` | 前 5 epoch 仅头 `1e-3`；之后头 `1e-4`、解冻编码器 `1e-5` |
| weight decay | `1e-4` | `1e-4` |
| batch size | 16，不丢弃末批 | 16，不丢弃末批 |
| 最多 epoch | 50 | 30，包含头部预热的 5 轮 |
| 早停耐心 | 连续 10 轮未改善 | 第 6 轮开始计连续 8 轮未改善 |
| 调度 | 固定学习率 | 仅上述阶段切换 |

第一版统一使用交叉熵和自然类别频率，不叠加重采样或类别权重，减少变量。类别失衡通过必报的逐类召回率和宏平均召回率揭示；若出现少数类持续失效，再将“训练集计算的逆平方根频率权重”作为后续新版本消融。

**训练损失与选型指标不同：** 交叉熵用于梯度学习；主选型指标仍为分型准确率。每轮在完整 76 张验证图上确定性预测；以正确数最多为最佳检查点，并列时取验证交叉熵更小者，再并列取更早 epoch。早停使用同一排序的严格改善，保存初始／预热期最佳状态，S3 允许最终最佳检查点来自预热期。

三种配置完成后，以各配置三个种子的验证正确数之和选胜者；并列时比较平均宏召回率，再按 S1、S2、S3 的预设顺序选择。**部署权重固定取胜出配置的 seed=42 检查点**，另外两种子衡量波动，不挑选最佳种子，不进行集成。第一批最多 `2×3×50＋3×30＝390` 个训练 epoch；冻结特征的 epoch 只训练线性头，不能等同于完整编码器训练开销。

## 6. 评价与 LLM 公平对照

1. 主指标为完整集合上的七类准确率，错误、失败和未完成样本都不从分母删除；未完成运行标记为未完成。辅助报告每类召回率、宏平均召回率、macro-F1、混淆矩阵、分来源表现、推理耗时与内存。
2. 三种配置在验证集报告三种子均值／标准差。选型完成后冻结模型、预处理、标签顺序及指标代码，再统一评价测试 119 张；可报告三种预设配置的全部种子作为对照，但测试成绩不能改变胜出配置或部署种子。
3. E1 baseline 与 E2 reference 是预设 LLM 对照。在同一 119 张测试图、同一图像版本上运行已冻结的提示／参数，每种重复 3 次并单独计费记录；小模型三种子与 LLM 三次随机采样分别报告，不能解释为同一种随机性。已完成的搜索集 E1/E2 只作背景，不填入测试对照表。
4. 小模型和当前 Agent 均只允许七类标签。Agent 仍可弃权，计为不正确；非法 CL 由解析器记为 error。不将历史 CL 输出事后映射为 CE1。
5. 如果做了图内文字遮挡或有效区域裁剪，旧 r1 结果不再是相同输入条件。新版测试必须让两种方法看到相同处理版本，E2 的参考图也使用对应处理版本。
6. 重点列出 CE4↔AE、CE1 错分去向和 CE2/CE3 小样本表现。报告差值及按已知关联组的配对 bootstrap 区间；重复种子不当作额外患者，当前关联组区间也不宣称是患者独立的临床区间。
7. 测速固定设备与 batch=1，记录包含解码／预处理的端到端耗时，注明预热、是否包含权重加载和加速器同步；LLM 另报 API 成本，不只比较 token 与本地训练时间。

v1 完成标准是训练和评价链路可复现、所有预设结果可追溯，不预设“必须超过 80%”。即使未超过 LLM，只要在类别上互补且成本低，也有后续工具研究价值；是否互补仍需同图实测。

## 7. confidence 与未来基础 Harness 接入

第一版保留未经校准的 softmax confidence，报告 5 个固定等宽区间的样本数、平均 confidence 和实际正确率，空箱为 N/A；可补充七类 NLL／Brier 作为分数质量诊断，不替换准确率主目标。softmax 大不保证可靠，可参考 [温度缩放原始论文](https://proceedings.mlr.press/v70/guo17a.html)。本版不拿反复用于选型的 76 张再宣称独立校准；未来有专门校准数据或严格折外预测时再拟合温度。

独立模型验证完成后，可新增 `expert` 工具模式：输入图像→小模型输出分型、完整分数向量→作为明确标注的辅助意见给 LLM。先做“LLM 单独／小模型单独／LLM＋小模型”对照，再考虑低置信度调用、分型门控或融合权重。小模型分数与 LLM 自评 confidence 的来源不同，不能共享一个未经验证的 0.8 阈值。

**后续 Auto Harness 的关键限制：** 小模型已用 search 标签训练，不能把它在 search 上的训练内预测当成公平动作缓存去优化门控。需在 search 内按关联组生成折外专家预测（每张图由未训练过所属组的模型预测，保持 reference 专属训练），或留出新的门控开发集。现有大关联组与少数类可能使分组分层折无法平衡，须检查每折类别；最终完整训练模型与折外模型也存在训练规模差异，要在独立验证阶段确认策略。未来联合系统应另行分配选型／测试资源，不能在本轮已读测试成绩后继续调门控并称其独立测试。

## 8. 实施顺序与产物

| 步骤 | 工作 | 产物 |
| --- | --- | --- |
| 1 | 核对患者关联、图内文字、标签、预训练重叠证据；冻结训练用途映射 | `configs/expert-typing/v1/split.json` 与审核记录 |
| 2 | 在现有 expert_lab 编码器基础上补七类数据加载、分类头、训练／评价入口 | 独立专家模块及必要测试 |
| 3 | 先用少量 train 图验证损失下降、保存／加载一致、冻结层不更新 | smoke 记录，不作为性能结果 |
| 4 | 提取两种冻结特征，运行 S1/S2/S3 的 9 次训练 | `runs/expert_typing/v1/<配置>/<种子>/` |
| 5 | 按预设验证规则选型并保存冻结声明 | 选型报告、最终权重指纹 |
| 6 | 对冻结的小模型及 E1/E2 完成相同测试图对照 | 测试逐图结果、混淆矩阵、成本和差异分析 |

每次训练保存 `config.json`、数据／划分／预处理／预训练权重哈希、环境版本、种子、`history.jsonl`、最佳检查点、验证预测与指标；测试产物另目录保存。检查点内保存类别顺序，加载时校验，避免七个输出索引错位。数据加载测试应覆盖 train/validation/test 关联组隔离，缓存校验应拒绝过期特征。

用户现有 Miniconda `he` 可以作为目标环境。实施前检查 Python、PyTorch、torchvision、timm 的兼容性；旧 expert_lab 曾验证 `torch 2.6.0 / torchvision 0.21.0 / timm 1.0.15`，这是历史可用组合，不代表已安装在 `he`。Apple Silicon 可先检测 MPS，冻结特征和线性头也可在 CPU 运行；根据一次开发侧 smoke 实测耗时后再决定设备，不预估未经测量的完成时间。

当前入口为 `scripts/experiments/train_typing_expert.py`，支持 prepare、train、select、evaluate、predict、compare；实现位于 `src/typing_expert/`。命令、产物和验证范围见 [运行指南](typing-classifier-v1-runbook.md)。旧 `expert_lab/src/run_experiment.py` 仍为参考池特征工具，不能代替七分类训练。患者／图内文字审核及预训练重叠核查仍待完成，当前清单和输出显式标记为内部探索。

本次数据和 split 已在原路径覆盖更新。旧权重和特征缓存不能作为当前数据的实验结果使用，须重新训练。历史 smoke 仅记录当时的实现验证。
